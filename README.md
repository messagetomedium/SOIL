# DIGITAL SOIL 0.1 — THE FIRST SEED

Работающий прототип цифрового растения для Debian Linux / Python 3.11+.
Один процесс растения сам создаёт, компилирует, исполняет, мутирует и удаляет
свой Python-код. Второй процесс — **SOIL OBSERVER** — только читает файлы
и текущую телеметрию. Отдельного управляющего Plant Runtime нет.

## Установка в Debian

Используйте отдельную VM и обычного пользователя. Команды `apt` выполняются
администратором только при подготовке; само зерно от root не запускается.
Общие папки Windows и доступ к личным данным отключите.

```sh
sudo apt update
sudo apt install python3 python3-venv libportaudio2 libgl1 libegl1 libopengl0 \
  libxkbcommon-x11-0 libxcb-cursor0 libxcb-icccm4 libxcb-image0 \
  libxcb-keysyms1 libxcb-render-util0 libxcb-xinerama0 fonts-dejavu-core
cd SOIL
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[test]'
```

Для воспроизводимой установки с [uv](https://docs.astral.sh/uv/):
`uv sync --locked --extra test`. Версии всех Python-зависимостей закреплены
в `uv.lock`. На ARM64 нужны доступные для вашей версии Python колёса NumPy,
PySide6, PyQtGraph и sounddevice; запуск на Raspberry Pi 5 ещё не проверен.
Интернет нужен при установке, но не для работы эксперимента.

## Первый запуск

Из корня проекта в активированном окружении:

```sh
python scripts/prepare_lab.py
python laboratory/plant_001/seed.py
```

Во втором терминале:

```sh
cd SOIL
. .venv/bin/activate
python -m observer.main laboratory/plant_001
```

`prepare_lab.py` только копирует исходное зерно и создаёт `environment.json`.
Готовых ветвей и звуковых органов он не создаёт. Повторный запуск сохраняет
живое зерно и ресурсы. `seed/seed.py` остаётся исходным образцом;
самозапись происходит только в `laboratory/plant_001/`. Вся лаборатория
исключена из Git. Чтобы начать новый опыт, остановите зерно, при необходимости
скопируйте текущую лабораторию, затем вручную удалите рабочий каталог
`laboratory/` и повторите подготовку. Само растение всю свою папку не удаляет.

Остановка — Ctrl+C. Закрытие Observer не останавливает растение. Его можно
открыть снова. При обычном перезапуске зерно восстанавливает текущие функции
из собственных файлов, проверяя их по текущему `body.json`; это не архив
истории. Проверка несовпадения файлов останавливает загрузку, чтобы не
исполнять несогласованное тело. Замены файлов атомарны по отдельности;
транзакция всех файлов при отключении питания не гарантируется.

## Что происходит

- Начальное тело — стабильное ядро без звуковых функций. При недостатке
  энергии оно остаётся в покое; при благоприятных ресурсах само прорастает.
- Первое определение `tissue_<id>` появляется непосредственно в области
  `# <soil:growth>` файла `seed.py`. Дальнейший рост создаёт новые определения
  там же и модули `branches/b_<id>/.../tissue.py`, включая вложенные ветви.
- Четыре правила тканей: осциллятор, пульсатор, резонатор и фильтр.
  Функции собираются из ограниченной грамматики NumPy-операций и констант.
  Нет готового взрослого графа или расписания появления органов.
- Новый код сначала проверяется по AST и допустимым операциям, компилируется,
  затем записывается и подключается в том же процессе. Ошибка обычной записи
  откатывает изменённый файл и не меняет действующий граф.
- Геном неизменяем. Соматическая мутация заменяет исходный текст и callable
  узла; может изменить связи с предшествующими узлами. Граф ацикличен:
  разветвлённые сигналы можно соединять в общем фильтре/резонаторе.
- Рост, мутации и отказ от неэффективных тканей зависят от энергии,
  стоимости содержания/обработки, сложности, активности узлов и звуковых
  метрик RMS/спектрального разнообразия. `sense()` — граница обратной связи
  для будущего внешнего аудиовхода; сейчас входа нет.
- Деградирующая ткань несколько секунд доступна Observer как `dying`, затем
  исчезает из исполняемого графа и исходников. Пустые ветви удаляются.
  Стабильное ядро сохраняется, даже если отмерли все звуковые функции.

Изменяйте **только ресурсы** в `laboratory/environment.json`, например:

```json
{"nutrients": 1.7}
```

Допустимый диапазон — 0–8. Значение 3–8 ускоряет накопление энергии и рост;
0 создаёт голодание и постепенное отмирание. Файл перечитывается каждые
0.5 секунды. При отсутствии/ошибке файла ресурсы считаются нулевыми.
По умолчанию 1.7 поддерживает небольшой организм и создаёт конкуренцию
за ресурсы при усложнении. Фиксированные моменты событий не гарантируются:
сеанс занимает несколько минут. Значения генома находятся в `Genome` исходного
зерна; скорость меняют через энергетические затраты и ресурсы, а не сценарий.

Для воспроизводимого опыта: `python laboratory/plant_001/seed.py --random-seed 17`.
Для ограниченного сеанса добавьте `--duration 120` (реальные секунды).
Фиксированный RNG воспроизводит биологические решения при одинаковых условиях
и последовательности шагов; задержки устройства/ОС могут менять обратную связь.

## Звук

Синтез — NumPy, выход — sounddevice/PortAudio, моно, по умолчанию 24 кГц,
блок 480 отсчётов. Фаза задаётся непрерывным счётчиком сэмплов, фильтры хранят
состояние между блоками. Изменения структуры сглаживаются коротким переходом;
есть DC-блокер, устранение NaN/Inf, мягкий ограничитель до ±0.16 и ограничение
скачка между соседними отсчётами. Начинайте с малой громкости системы.

Аудиоколбэк только забирает готовый блок из ограниченной очереди и копирует
его в выход; при нехватке выдаёт нули. Файловые операции, компиляция и синтез
работают в основном потоке растения. Это Python-прототип, а не гарантированная
система жёсткого реального времени: большие задержки ОС могут давать пропуски.
Их число передаётся в поле `audio.underflows` телеметрии.

Включите звуковую карту в настройках VM и проверьте устройства:

```sh
python -m sounddevice
```

PortAudio использует системное устройство по умолчанию. Для выбора устройства
задайте системный выход ALSA/PulseAudio/PipeWire перед запуском. Если устройство
недоступно или не принимает частоту, зерно продолжает расти и синтезировать
диагностический буфер. Для явной работы без устройства:

```sh
python laboratory/plant_001/seed.py --no-audio
```

В Observer видны текущие волна, спектр, RMS и статус аудиобэкенда. Постоянная
запись WAV не ведётся. В этой облачной среде проверен тестовый тракт;
физический аудиовыход и слышимость на VM требуют проверки на вашем устройстве.

## Observer и протокол

Три представления расположены вертикально: действующий граф, настоящий текст
исходников и цветовая карта тканей. Сверху отдельно выводятся метрики и
диагностические волна/спектр. Зелёный — новый узел, серый — устойчивый,
красный — отмирающий. Каждая полоса карты соответствует реальной функции,
её пути и диапазону строк. Обычное наведение выделяет код и узел без клика.
При физическом удалении исчезают исходник/полоса/узел. Отдельный узел графа
показывает сохранённое ядро. Горизонтальные координаты связаны с глубиной
файловых ветвей, рёбра направлены от входных узлов к обработчикам.

Observer опрашивает файловое дерево раз в 250 мс и индексирует его через `ast`;
неизменившиеся файлы повторно не разбираются. Он никогда не импортирует
растение, не исполняет его модули и не содержит алгоритмов жизни.

Телеметрия — Unix Stream Socket `plant_001/telemetry.sock`, права `0600`.
Растение отправляет до пяти снимков в секунду, каждый — UTF-8 JSON + `\n`:

```json
{
  "protocol": "digital-soil", "version": 1,
  "pid": 1234, "age": 12.5, "energy": 6.2, "resources": 1.7,
  "nodes": [{"id": "012345abcdef", "kind": "oscillator", "path": "seed.py",
    "parents": [], "born": 2.0, "revision": 0, "state": "stable",
    "dying_since": null, "sha256": "...", "activity": 0.12}],
  "source_bytes": 32000,
  "metrics": {"rms": 0.02, "richness": 0.1, "processing_seconds": 0.001},
  "wave": [], "spectrum": [], "counters": {}, "error": "", "audio": {}
}
```

`wave` — максимум 256 отсчётов, `spectrum` — 64 линейно расположенные
диагностические амплитуды между 0 и частотой Найквиста. `parents` задаёт
вычислительные входы, ID совпадает с суффиксом имени функции. Снимок содержит
только текущее состояние. До четырёх слушателей; медленный клиент отключается
при накоплении 128 КиБ. Растение **не читает** данные клиентов; командного
канала нет. Клиент автоматически переподключается, в том числе после
перезапуска растения. Длина Unix-пути ограничена — размещайте лабораторию
по короткому пути. Разрывы соединения не останавливают рост.

## Проверки

```sh
python -m pytest -q
# Без рабочего стола, но с настоящими Qt-виджетами и событиями мыши:
QT_QPA_PLATFORM=offscreen python -m pytest -q
```

Тесты проверяют физический рост обоих уровней, горячее исполнение и загрузку
тела после перезапуска; изменения кода/сигнала при мутации; изменение связей;
удаление файлов и inline-функций; голодание; фазу, DC/NaN/амплитуду, очередь
колбэка; отказ записи и лимиты; обход путей, симлинки, hardlink и запрещённые
конструкции; живой отдельный процесс, переподключение; реальные Qt-события
наведения с проверкой выделенного текста и ID узла.
Тесты Unix-сокетов требуют разрешения локального IPC. Успех Qt offscreen не
подтверждает настройку графического рабочего стола или физической звуковой карты.

Ручная проверка в VM: запустите оба процесса, дождитесь роста, наведите курсор
на полосу и сравните выделенную функцию/узел; закройте и откройте Observer;
поднимите ресурсы, затем задайте 0 и дождитесь красных тканей и удаления кода.
Звук должен меняться вместе с действующим графом. После опыта верните ресурсы.

## Границы безопасности и версии

Зерно запрещает root и запуск исходного образца вместо рабочей копии. Запись
через Linux `dir_fd`/`O_NOFOLLOW`, запрет `..`, симлинков и hardlink ограничивают
операции своим деревом. Один писатель защищён `flock`. Генерируемые функции
не могут импортировать, обращаться к системе или вызывать произвольные методы;
AST проверяется вместе с закрытым списком операций и пустыми builtins.
Это **не песочница для чужого Python-кода**: исходное ядро и зависимости
должны быть доверенными, лаборатория — приватной, без враждебного второго
писателя. Не редактируйте исполняемый код живого растения вручную.

По умолчанию: не более 24 звуковых узлов (жёсткий максимум 48), 256 КиБ
исходников (максимум 512 КиБ), 64 исходных файла, глубина ветвей до 4,
не чаще одной структурной самозаписи за 0.4 с. Дополнительно хранятся только
текущий снимок тела, lock и сокет; аудио/телеметрия имеют ограниченные буферы.
CLI ограничивает будущие выделения heap/mmap через Linux `RLIMIT_DATA`
до 512 МиБ. Программа не запускает оболочку/другие процессы, не устанавливает
пакеты и не использует IP-сеть; единственный сокет — локальная телеметрия.
Защита путей не заменяет изоляцию VM и ограничения ресурсов ОС.

Размножение, другие растения, внешний слух, полное самоудаление, история,
нейросети, Digital Soil OS и удалённое управление не реализованы.
